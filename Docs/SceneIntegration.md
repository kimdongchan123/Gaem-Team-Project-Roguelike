# 로비·룸시스템 플레이어 연결

`LobbyScene`과 `RoomSystemTest`가 공유하는 `Assets/Prefabs/Player_Test.prefab`에
`PlayerSceneInstaller`를 연결했다. 씬에 이미 배치된 플레이어를 그대로 사용하므로
카메라, 스폰 매니저, NPC, 룸 트리거의 기존 플레이어 참조가 유지된다.
임시 이동 스크립트는 실제 플레이어 시스템으로 대체된다.

## 확인 순서

1. `LobbyScene`에서 플레이한다. 로비를 WASD로 이동하고 Shift로 대시할 수 있다.
2. 스탯 NPC 근처에서 E를 누르면 저장되는 6종 강화 화면이 열린다. 닫기 또는 Esc로 닫는다.
3. I로 무기·소모품 가방을 열고 로비 보관함을 이용한다.
4. 던전 입구에서 E를 눌러 `RoomSystemTest`로 이동한다. 강화와 보유 아이템은 유지된다.
5. 플레이어는 기존 `DungeonEntrySpawn`에 생성된다. 카메라·벽·잠긴 문·안개 시스템을 유지한다.
6. 전투방에서 공격하고 몬스터를 모두 처치하면 문이 열린다. E로 크리스탈을 줍는다.
7. 사망하면 실제 방 ID와 처치·보상·무기 손실을 표시한다. 로비 복귀 버튼은 `LobbyScene`을 불러온다.

`RoomSystemTest`만 직접 플레이해도 실제 플레이어 시스템이 자동 설치되고
저장된 강화·가방으로 새 전투를 시작한다. 로비에서는 전투와 피격을 막으며,
강화·가방·상점 창을 열면 이동·공격과 전투 시간이 정지한다.
기존 상점의 임시 구매 데이터/골드 체계는 유지하며 이번 연결에 실제 구매 경제를 추가하지 않았다.

## 구현

- `PlayerSystemFactory`: 샘플·실제 씬에서 동일한 능력치, 가방, 무기, HUD, 한국어 UI를 설치한다.
- `PlayerSceneInstaller`: 기존 프리팹에 설치하고 로비/던전 모드 및 카메라·룸·스포너를 연결한다.
- `PlayerRunSession`: 씬 이동 전 가방 저장, 실제 던전 시작, 사망 정산 후 실제 로비 복귀를 처리한다.
- `PlayerMovement`: Rigidbody2D가 있는 씬에서는 고정 물리 업데이트로 이동해 벽과 문 충돌을 지킨다.
- `LobbyStatsUI`: 기존 NPC 참조를 유지하면서 샘플의 영구 강화 UI로 연결한다. 임시 스탯 포인트는 사용하지 않는다.
- `MonsterSpawner`: 연결된 방의 소환 몬스터가 모두 사망하면 `ClearRoom()`을 호출한다.
- `RoomSystem.CurrentRoomChanged`: 전투 결과의 최종 방 위치를 갱신한다.

샘플 씬의 테스트 몬스터·아이템 생성은 `SampleScene`에만 남아 있다.
사용자가 수정해 둔 빌드/셰이더 프로젝트 설정은 변경하지 않았다.
빌드 씬 목록에는 `LobbyScene`, `RoomSystemTest`가 활성화되어 있어야 한다.

## 자동 검증

`./Tools/CombatValidation/Run.ps1`는 별도 임시 프로젝트에 실제 에셋·씬을 복사한다.
테스트 전용 회사/제품명과 저장 키를 사용해 사용자 저장을 수정하지 않는다.
기존 전투·강화 검증 후 실제 로비 진입, NPC UI, 물리 이동과 벽·대시 충돌,
던전 입장과 스폰, 방 전투·문 해제, 보상·사망·로비 복귀 및 던전 직접 시작을 검사한다.
실제 렌더링의 외관은 Game 뷰에서 확인한다.

검증 결과: 빌드 오류·경고 0개, 기존 기능 및 실제 씬 통합 검증 352개 통과.
`RoomSystemTest`의 `CameraBounds` 오브젝트 2개에는 작업 전부터 소스가 없는
스크립트 GUID `c2c2380be79e7a84dae4684f604b522b`가 연결되어 있다.
이 기존 누락 참조는 변경하지 않았으며, 현재 `PlayerCameraController`의 추적은 유지된다.
